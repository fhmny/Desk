# Creative Desk — التصميم المعتمد للتنفيذ

**التاريخ:** 2026-11-25. **الحالة:** تنفيذ أول إصدار داخل `desk/` فقط.

## الغرض

مكتب تصميم ومونتاج لمدرسي فهمني. المدرس يرسل طلب صورة أو فيديو مع وصف ومراجع، والمصمم المسند له يناقش التفاصيل ويسلم العمل برابط Google Drive. الأدمن يرى كل الحسابات والطلبات والمحادثات والرصيد، ويتحكم في توزيع العمل.

## حدود المشروع

- كل الكود والوثائق الجديدة داخل `desk/frontend`, `desk/backend`, `desk/docs`.
- لا تعديل على `client`, `server` أو تطبيق الحضور في هذه المرحلة.
- للـDesk حسابات دخول مستقلة مؤقتًا. ربط الدخول بالمنصة قرار نشر لاحق، ويتطلب عقد تكامل منفصل.
- الواجهة React وTypeScript، والباك Python FastAPI مع قاعدة SQLite افتراضية للتطوير. يمكن ضبط `DESK_DATABASE_URL` لقاعدة إنتاج مناسبة.
- لا رفع ملفات ولا تخزين صور أو فيديو على سيرفر الـDesk أو المنصة. الرسائل وروابط HTTPS فقط تُحفظ في قاعدة البيانات. روابط التسليم من Google Drive.

## الأدوار

| الدور | الصلاحيات |
|---|---|
| الأدمن | إضافة المدرسين والمصممين، تفعيل/إيقاف الحسابات، إسناد المدرسين، تحديد رصيد الصور والفيديو، رؤية كل الطلبات والمحادثات والروابط، وإلغاء الطلب لسبب موثق. |
| المدرس | رؤية رصيده وطلباته فقط، إرسال وصف ومراجع، المحادثة، مراجعة رابط التسليم وطلب تعديل على نفس الطلب. |
| المصمم | رؤية طلبات المدرسين المسندة إليه فقط، قبول الطلب، المحادثة، إضافة رابط المسودة والنهائي، والضغط على «تم التسليم». |

## الرصيد ودورة الطلب

لكل مدرس عدد صور وعدد فيديوهات مستقلان. إنشاء الطلب لا يخصم رصيدًا. قبول المصمم أو الأدمن يحجز خانة واحدة من نوع الطلب. المصمم يضيف رابط Drive نهائيًا ثم يضغط «تم التسليم»؛ تتحول الخانة المحجوزة إلى مكتملة فورًا. المدرس لا يعتمد الخصم. إذا طلب المدرس تعديلًا، يظل نفس الطلب محتسبًا كمكتمل ولا يخصم ثانية؛ المصمم يمكنه إضافة نسخة جديدة وإعادة التسليم. إلغاء الأدمن قبل التسليم يحرر الخانة المحجوزة. لا يمكن تقليل الرصيد الكلي إلى أقل من المحجوز والمكتمل.

الأدمن يقدر ينقل مدرسًا إلى أي مصمم نشط. عند النقل، كل طلبات المدرس الموجودة، بما فيها المكتملة، تنتقل إلى المصمم الجديد مع المحادثات والروابط؛ المصمم القديم يفقد إمكانية عرضها أو الرد عليها فورًا. الطلبات الجديدة تذهب للمصمم الجديد أيضًا. الأدمن يظل قادرًا على رؤية الكل.

الحالات: `submitted → accepted → in_progress → completed`، و`completed → revision_requested → completed`. الإلغاء قبل اكتمال الطلب ينتقل إلى `canceled`.

## البيانات

حسابات المستخدمين: الاسم، البريد، كلمة مرور مجزأة، الدور، النشاط، المادة، روابط Facebook وTikTok وYouTube للمدرس. الطلب: المدرس، المصمم، نوع الطلب، العنوان، الوصف، الحالة والتوقيت. الرسائل والروابط مرتبطة بالطلب وصاحبها. سجل للأحداث المؤثرة مثل الإسناد، القبول، التسليم والإلغاء. لا أعمدة بيانات ثنائية للوسائط ولا نقطة API لرفع الملفات.

## القرارات التشغيلية المفتوحة

الباقات والأسعار، حدود مدة الفيديو، عدد التعديلات المضمنة، ميعاد التسليم المتفق عليه، الاستضافة، وربط حسابات فهمني. هذه لا تمنع تجربة الإصدار المحلي الحالي، لكنها لازمة قبل البيع أو النشر العام.
