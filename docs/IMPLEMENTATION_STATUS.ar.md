# حالة تنفيذ Creative Desk

**التاريخ:** 2026-11-25

## المنفذ الآن

- مشروع مستقل تمامًا داخل `desk/`، بواجهة React/TypeScript وخدمة FastAPI/Python.
- دخول منفصل وحساب أدمن أولي محمي بسر إعداد، وحسابات مدرسين ومصممين ينشئها الأدمن.
- الأدمن يرى كل الطلبات والمحادثات، المدرسين والمصممين، رصيد كل مدرس، وآخر أحداث التشغيل.
- إسناد مدرس لمصمم واحد وضبط رصيد الصور والفيديو على حدة.
- طلب صورة أو فيديو بوصف وروابط مراجع HTTPS. لا توجد نقطة رفع ملفات.
- محادثة لكل طلب، وروابط Google Drive للمسودات والنتائج النهائية.
- المصمم هو من يضغط «تم التسليم»، وحينها تُحسب خانة من نوع العمل مكتملة. طلب التعديل على نفس الطلب لا يخصم مرة أخرى.
- صلاحيات الوصول تمنع المصمم من رؤية طلبات مصمم آخر. جلسات الدخول تخزن مجزأة في قاعدة البيانات.

## ما تم التحقق منه

- `py -3 -m pytest -q` داخل `desk/backend`: أربعة اختبارات ناجحة تغطي التدفق الأساسي والعزل والرصيد والإلغاء ونقل المدرس والديمو.
- ملف `seed_demo.py` ينشئ قاعدة `desk-demo.db` مستقلة فيها 6 حسابات و7 طلبات وهمية. اختباره يتأكد من الأدوار والعزل والرصيد وعدم الكتابة فوق قاعدة موجودة.
- فحص نحوي لملفات TypeScript/TSX الأربعة باستخدام TypeScript transpiler متاح محليًا: ناجح.

## ما يلزم قبل نشر إنتاجي

- تشغيل `npm install` ثم `npm run build` وفحص الواجهة في المتصفح. تنزيل الحزم من npm لم يكتمل في البيئة الحالية، والكاش المحلي لا يحتوي على كل الحزم.
- اختبار التحميل والتفاعل على الموبايل والشاشات الكبيرة بعد بناء الواجهة.
- نقل قاعدة البيانات من SQLite التطويرية إلى قاعدة إنتاج، وإضافة migrations ونسخ احتياطي.
- ضمان حجز الرصيد ذريًا مع الطلبات المتزامنة قبل تشغيل أكثر من عامل أو إتاحة خدمة مدفوعة لعدد كبير.
- إضافة حدود لمحاولات تسجيل الدخول، وآلية استرجاع/تغيير كلمة المرور، وضبط استضافة HTTPS.
- تحديد سياسة تسوية النزاعات، عدد جولات التعديل، الأسعار ومدد التسليم.
- ربط تسجيل الدخول مع منصة فهمني إذا تقرر ذلك لاحقًا؛ المشروع الحالي لا يمس `client/` أو `server/`.
